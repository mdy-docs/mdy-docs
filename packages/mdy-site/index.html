Every document carries its own data.

A file is a set of documents. Each one holds YAML and a template written in MDY. The set goes into a query engine, the templates run in a sandbox, and one of them decides what all of it becomes — a page, a feed, a whole site.

How a file becomes a page

Five passes, and the third one is the interesting one

Nothing here is a plugin chain you configure. It is the same five steps every time, and a document can reach the ones after it.

  1. Split

    Bare --- lines cut the file into documents; the first +++ in each cuts YAML from body.

  2. Store

    Every document's data goes into an in-memory nisaba collection, so a template can query the set it belongs to.

  3. Compile

    The body becomes one statement sequence, so a const in one tag is visible to every later tag.

  4. Run

    Inside the lamassu VM, with the document's data as res.data and the caller's as req. The output is MDY source.

  5. Render

    That source is parsed to hast — an HTML syntax tree — and stringified. React swaps in at this step and nothing above it changes.

Document sets

A file is a set, and the set is queryable

Documents are anonymous and positional, so nothing addresses anything by index. Give them attributes and both the data and the template become queries — adding a member is appending a document, and nothing else changes.

CallWhat it gives you
$.find(query)Data of every match, in document order — full Mongo operators
$.findOne(query)The first match, or null
$.render(t, data)Run a document with data as its req; gives back its finished tree
$.text(t, data)The same render as the text its code wrote, for output that was never markup
$.withTag(tag)Every document that mentions #tag in its text
$.emit(path, content)Produce a named output — this is what builds a site
$.parse(source)MDY source to a tree, to walk or rewrite
$.markdown(md)Markdown text through the other front end, to the same kind of tree
$.table(rows, align)A 2-D array as a table, cells read as MDY
$.toc()A contents list of this document's final headings, after every transform
transform(fn)Rewrite the finished tree, inside the sandbox, before it becomes HTML

Tags are known without rendering

A #tag written in a body is scanned out of the source before any template runs, so $.withTag('release') can select documents the engine has not executed. That is what keeps a query over a thousand-file directory cheap.

Links and @mentions are collected the same way, and a link to another page of your own is lower-cased with its spaces as dashes on the way past.

Sandbox

Template code cannot reach the host

Documents execute in a JavaScript-subset interpreter compiled to WebAssembly, with the engine's own bounded CPU, memory and stack. Template code can reach exactly two things: its own data, and the document set. 

%% write(typeof process)
%% write(' / ')
%% write(typeof Function)

Both are undefined

There is no host runtime behind the template, so there is nothing to escape into — no filesystem, no network, no process, and no way to build a function out of a string.

Which means a document from somewhere else is safe to render. For most template engines that sentence needs a paragraph of caveats after it.

Static sites

No content/, no layouts/, no site.yaml

Every site is a script-defined site. There is no convention deciding what a path means — one entry document decides all of it, in template code. Which files are posts, what URL each gets, how tags group, what the feed contains. 

%% for (const post of $.withTag('post')) {
     const html = $.render({template: 'page'}, post)
     $.emit(post.slug + '/index.html', html)
%% }
%% $.emit('feed.xml', $.render({template: 'rss'}))

Four things the script cannot do itself

Image resizing, the search index's tokeniser, RFC-822 dates (the VM has no clock), and turning assembled source into HTML. Those are host natives. None of them carries any policy — the script still decides which images, what is searchable, what is in the feed.

A site can import another mdy project the way code imports a package — a theme is a directory with its own document set, reached through its own $. Swap the import and only the look changes.

Command line

One file, one directory, or a whole site

mdy report.mdy                        # generated source on stdout
mdy report.mdy --html -o report.html  # an HTML file
mdy report.mdy -o out.mdy --watch     # re-render on every save
cat report.mdy | mdy - --html         # stdin, straight through

mdy ./my-site                         # scan the directory, run main.mdy
mdy build ./my-blog --out ./dist      # build the whole site
mdy dev ./my-blog                   # dev server, watch, live reload

A directory input inserts every file under it as a document — path, name, extension, size, modified time, plus front matter for .mdy files — and the entry document reaches any of them. Nothing interprets what a path means before the script does.
